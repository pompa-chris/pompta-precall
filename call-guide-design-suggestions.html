Call Guide — Design Simplification Ideas

How to make the live call guide faster to scan mid-call without removing any information.

Core principle: During a live call, the caller needs exactly ONE thing — the script text to say. Everything else (instructions, tips, alt scripts) is support material that should be accessible but not competing for attention. Reduce visual noise. Elevate the script. Hide-but-don’t-delete everything else.
1 Collapse Instructions & Tips Into Expandable Rows High Impact
Problem Every step shows 3 text blocks stacked vertically: instruction paragraph, script card, and tip callout. On a live call, the caller has to scan past the instruction and tip to find the script. The instruction and tip are training content — useful when learning, noise when performing.
Solution Collapse instructions and tips into slim, clickable bars. They expand on tap but stay collapsed by default. The script card becomes the first thing the eye hits.

2 Move Alt/Extra Scripts Behind “If…” Toggles High Impact
Problem Steps like Device Push show the primary script, then an alt script (“If they say just my phone”), then sometimes an extra script — all visible at once. On a call, the caller reads the primary, delivers it, then has to quickly scan past it to find the response for the client’s answer. The alt/extra scripts add height and visual clutter that’s irrelevant 50-70% of the time.
Solution Show ONLY the primary script in the card. Alt and extra scripts become labeled toggle cards below it — collapsed by default, expanding on click. The label previews enough context (“If they say ‘just my phone’…”) so the caller knows which one to tap.

3 Add a “Focus Mode” Toggle High Impact
Problem The guide serves two purposes: (1) training — reading through at your desk, learning the flow, and (2) live use — glancing at it mid-call for the exact words. These have opposite needs. Training needs all the context. Live needs minimal distraction. One UI tries to do both.
Solution Add a “Focus Mode” toggle in the top bar (next to Quick Jump). When ON: collapses instructions, tips, and alt scripts automatically. Larger primary script text. Muted background. When OFF: everything visible (current behavior). Persists via localStorage so they don’t re-toggle every call.

4 Tooltip Info Dots on Key Terms Medium Impact
Problem Scripts reference things like “the neurotoxicity assessment,” “the test kit,” or “{HAName}” without context. A new caller may not remember what NTA link to send, or where to check kit tracking. This context is currently in the instruction/tip text — which in Focus Mode would be collapsed.
Solution Add small info-dot icons (ⓘ) next to key terms inside the script text. On hover/tap, a tooltip shows the quick reference (link to send, where to check, etc.). The script stays clean — context is there if needed but invisible if not.
Script with tooltip info dots
Say This
“It looks like you were able to complete the neurotoxicity assessmenti NTA Link: apply.pompaworkshop.com/login
HubSpot field: ntq_percentage
Secondary: apply.pompaworkshop.com/register-secondary questionnaire — that long questionnaire online. Awesome!”
Good for: NTA (link + HubSpot field), test kit (Slack channel + tracking portal), Zoom (test call link), spouse (links to Spouse Live Guide). Keeps operational details accessible without cluttering the reading flow.
5 Sticky Action Buttons Medium Impact
Problem Action buttons (“They’re engaged → Next,” “Went to voicemail”) sit at the bottom of the step content. On longer steps (NTA, Kit, Spouse), the caller has to scroll past the script card, tip, and alt scripts to reach the buttons. On a live call, scrolling = wasted seconds.
Solution Pin the action buttons to the bottom of the viewport as a sticky footer bar. They’re always visible regardless of scroll position. Use compact horizontal pill buttons to save space.

6 Variable Highlighting in Scripts Medium Impact
Problem Placeholders like {FirstName}, {HAName}, {Day}, {Time} are shown as plain italic text. The caller has to mentally parse where to substitute while reading. On a fast call, they might accidentally read “{HAName}” out loud.
Solution Render placeholders as small highlighted pills with a distinct color (yellow background or dashed underline). They pop visually so the caller knows “fill this in” at a glance.

7 Compact Step Title With Inline Badge Medium Impact
Problem The badge (“Step 3”) and title (“Zoom Access & Calendar Invite”) take two lines. The badge is on its own row, then the title is 32px below it. This wastes vertical space and pushes the script card down.
Solution Put the badge inline with the title on the same line. Reduce title size slightly in Focus Mode. One line instead of two.

8 Keyboard Shortcuts for Power Users Medium Impact
Problem Navigating requires clicking buttons. On a desktop call (Aloware + HubSpot open), the caller’s mouse is busy in other windows. Switching to click “Next” in the call guide tab costs focus.
Solution Add keyboard shortcuts: 1/2/3 = select action button by position. B = back. J = open Quick Jump. C = copy script. Show a tiny “?” help button in the top bar. For callers who keep the guide in a side panel, this means zero mouse usage.
Implementation: Simple keydown listener. Only fires when no input/textarea is focused. The “?” button shows a small overlay with the shortcut list.
